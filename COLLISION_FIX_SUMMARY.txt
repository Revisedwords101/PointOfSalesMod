🔧 WHAT WAS WRONG:
================================================================================

BEFORE (INCORRECT):
    BlockBehaviour.Properties.of()
        .mapColor(MapColor.STONE)
        .strength(3.0f)
        .noCollission()  // TYPO + MAKES BLOCK PASSABLE!
        .requiresCorrectToolForDrops()

PROBLEM:
- `.noCollission()` (typo for `.noCollision()`) makes the block passable
- Even with correct spelling, `.noCollision()` prevents collision detection
- Block had no physical collision shape or used wrong dimensions

================================================================================

✅ WHAT I FIXED:
================================================================================

1. ✅ REMOVED `.noCollision()` / `.noOcclusion()` from properties
   - Now uses default collision behavior (solid block)
   
2. ✅ UPDATED COLLISION SHAPE to inner box
   BEFORE: `Block.box(0, 0, 0, 16, 64, 16)` (full outer box)
   AFTER:  `Block.box(4, 4, 4, 12, 60, 12)` (inner box for collision)

WHY INNER BOX?
- Minecraft uses the collision shape to determine if players can walk through
- Full outer box looks correct visually but allows walking through
- Inner box (smaller than visual size) prevents walking while maintaining appearance
- This is standard practice for decorative blocks in Minecraft

3. ✅ ADDED `.noGravity()` to prevent block from falling
   - Vending machines shouldn't fall like sand or gravel

🎮 HOW COLLISION WORKS NOW:
================================================================================

Block Properties:
- Strength: 3.0f (solid, unbreakable by hand)
- MapColor: STONE (visual appearance)
- No gravity (won't fall like sand/gravel)
- Default collision (solid to players and entities)

Collision Shape:
- Inner box: x=4 to x=12, y=4 to y=60, z=4 to z=12
- This is smaller than visual size (16x64x16)
- Prevents walking through while maintaining correct appearance
- Standard practice for decorative blocks

Visual vs Collision:
- Visual size: 16×64×16 pixels (full block height)
- Collision size: 8×56×8 pixels (inner box)
- This is how most Minecraft blocks work!

================================================================================

🔧 TECHNICAL EXPLANATION:
================================================================================

Why Use Inner Box for Collision?

1. Visual Appearance: Block renders at full 16×64×16 size
2. Collision Detection: Uses smaller inner box (4-12, 4-60, 4-12)
3. Player Interaction: Can click from anywhere on visual surface
4. Prevents Walking Through: Inner box blocks player movement

This is standard Minecraft block design where:
- Visual size ≠ Collision size
- Inner collision box prevents walking through
- Full visual rendering maintains correct appearance
